# 已知问题：SSE 重连断点续传未实现（`last_event_id` 只解析不过滤）

**状态**：⚠ 已登记（设计使然，非缺陷；补齐需独立特性）
**影响面**：客户端断线重连后会收到重复事件，仓库内无任何客户端消费该参数
**首次定位**：2026-11-17（全仓审查）
**登记方式**：字段保留 + 本档案，避免后人重复踩坑

## 现象

`crates/sisyphus-bridge/src/http/sse_handlers.rs` 的 `SseQuery.last_event_id`
仅从 URL 解析、尚未参与过滤。重连客户端携带 `?last_event_id=<uuid>` 仍会
收到全部历史回放，无断点续传语义。

## 根因

- 事件 ID 为每次推送生成的随机 UUID，重连携带的 ID 无可匹配的历史；
- 仓库内无任何客户端消费该参数；
- 补齐需要引入带序号的全局事件日志，属独立特性，非当前字段的修复。

## 为何保留字段

去掉字段会让传该参数的客户端报 400/422 而非静默忽略，破坏既有 API 契约。
此处**不是**「为审计保留」，而是「解析已实现、过滤待实现」。

## 闭环条件

引入全局事件日志后，过滤逻辑上线并补「重连只收新事件」集成测试，本档案方可关闭。
