# Sisyphus 单机核心功能打磨开发计划 (Single-Node Refinement Plan)

**状态:** 活跃执行中（2026-11-22）  
**核心指导原则:** 聚焦单机闭环、极致性能、严格测试驱动（TDD）、坚守项目各项质量门禁。

---

## 一、 开发目标与范围

根据最新路线图调整，Sisyphus 暂缓分布式与集群化扩展，全面聚焦于**单机部署下的极致稳定性、认知循环精度、沙箱安全隔离以及终端交互体验**。

---

## 二、 核心阶段与任务分解

### 阶段一：认知循环与错误自愈增强 (`sisyphus-core`)
- **目标:** 提升 DAG 执行流在复杂单机任务中的容错与自反思能力。
- **具体任务:**
  1. 优化 `execute_with_cognition` 中的“反思（Reflect）”阶段，增加对常见工具错误（如编译报错、测试失败）的自动修正提示。
  2. 增强错误枚举变体（`CoreError`），确保所有内部错误均有清晰的上下文传播，杜绝任何非测试代码中的 `unwrap()`。
  3. 为认知循环核心路径补充基准测试（Criterion benchmark），评估单机推理与调度开销。

### 阶段二：沙箱与本地系统隔离强化 (`sisyphus-sandbox` & `sisyphus-sandboxd`)
- **目标:** 确保单机本地执行（文件读写、Bash 命令、构建测试）具备高强度的安全边界。
- **具体任务:**
  1. 完善 wasmtime 沙箱对本地系统调用的限制策略。
  2. 加强 `sisyphus-sandboxd` 守护进程在单机多进程隔离下的健康检查与资源回收。

### 阶段三：本地知识图谱与状态持久化 (`sisyphus-mem` & `sisyphus-knowledge`)
- **目标:** 实现长任务运行中的上下文永不丢失与高效检索。
- **具体任务:**
  1. 优化 `sisyphus-knowledge` 的资产管理与向量化摘要，加速本地知识召回。
  2. 强化 `sisyphus-mem` 对会话状态和 Todo 计划的原子化写入与异常恢复机制。

### 四、 终端体验与本地 Web 仪表盘 (`sisyphus-cli` & `webui`)
1. **TUI（`sisyphus-cli`）可视化升级:**
   - 优化 ratatui 界面对 DAG 节点实时状态的动态渲染。
   - 增加快捷键支持，方便用户在终端直接查看子任务日志与 Token 消耗。
2. **Web 仪表盘精进:**
   - 优化 axum + HTMX + SSE 的本地 Web 界面响应速度与实时数据推送。

---

## 三、 质量保障与门禁遵从

所有开发任务必须严格遵守项目现有的自动化门禁系统：
- **格式化与 Lint:** 严格遵循 `cargo fmt` 与 `cargo clippy`（基于 `rust-toolchain.toml`）。
- **脚本审计门禁:** 每次迭代必须通过 `make audit`（包含版本一致性、文档计数、TODO 勾选证据、LLM 作用域 spawn 边界等检查）。
