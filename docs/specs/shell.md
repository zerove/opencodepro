# Shell/Bash AI 开发规范 (Shell AI Spec)

## 1. AI 协同编码标准 (Coding Standards)
- **防御性编程 (Defensive Scripting)**：强制要求 AI 在脚本开头添加 `set -euo pipefail`。
  - *理由*：确保脚本在任何命令失败、引用未定义变量或管道错误时立即退出，防止连锁破坏。
- **变量安全**：强制要求所有变量引用必须加双引号 (e.g., `"$VAR"`)，严禁直接使用 `$VAR`。
- **幂等性设计**：引导 AI 编写具有幂等性的脚本（即多次运行结果一致），例如在创建目录前先检查 `if [ ! -d ... ]`。

## 2. 定向提示策略 (Prompting Patterns)
- **安全漏洞审计**：*“请检查此脚本是否存在 Shell 注入风险，特别是处理用户输入的部分，并使用安全的方式进行过滤。”*
- **环境兼容性分析**：*“请确保此脚本在 Ubuntu 22.04 和 macOS (zsh/bash) 之间具有良好的兼容性，避免使用非 POSIX 标准的特性。”*
- **模块化重构**：*“请将此长脚本重构为多个小型函数，并为每个函数添加清晰的输入/输出注释。”*

## 3. AI 质量验收清单 (Validation Checklist)
- [ ] **错误处理**：是否所有关键命令都检查了返回值？
- [ ] **路径安全**：是否使用了绝对路径或正确定义的变量路径，而非依赖不可靠的相对路径？
- [ ] **清理机制**：脚本是否在退出（包括异常退出）时正确清理了临时文件（使用 `trap`）？
- [ ], **权限最小化**：脚本是否尝试以 `root` 运行不必要的命令？

## ❌ 常见 AI 误区 (Anti-Patterns)
- **不安全的文件解析**：使用 `ls` 或 `find` 的结果直接通过 `for` 循环处理（容易被文件名中的空格破坏）。$\rightarrow$ **正确做法**：使用 `while read` 结合 `find -print0`。
- **环境变量依赖**：在脚本中直接使用 `$PATH` 且未在开头显式定义。$\rightarrow$ **正确做法**：在脚本开头明确设置必要环境变量或使用绝对路径。
- **忽略标准错误**：使用 `> /dev/null 2>&1` 掩盖所有错误。$\rightarrow$ **正确做法**：将错误定向到专门的日志文件，方便排查。
