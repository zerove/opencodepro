# Rust AI 开发规范 (Rust AI Spec)

## 1. AI 协同编码标准 (Coding Standards)
- **所有权与生命周期显式化**：强制要求 AI 在复杂结构中显式标注生命周期 (`'a`)，而非依赖编译器推导。
  - *理由*：显式的生命周期标注能强制 AI 在生成代码前重新思考内存布局，大幅减少 `borrow checker` 报错。
- **错误处理模式**：禁止在生产代码中使用 `.unwrap()` 或 `.expect()`。强制 AI 使用 `thiserror` 或 `anyhow` 构建完整的错误链。
- **零成本抽象 (Zero-cost Abstractions)**：引导 AI 优先使用 `Trait` 和泛型实现多态，而非 `Box<dyn Trait>`。

## 2. 定向提示策略 (Prompting Patterns)
- **借用检查预审**：*“在编写此函数之前，请先分析数据的所有权流转，并说明为什么这种借用模式不会导致生命周期冲突。”*
- **并发安全审计**：*“请分析该 `Arc<Mutex<T>>` 的锁粒度是否过大，并尝试使用 `RwLock` 或原子操作进行优化。”*
- **内存布局优化**：*“请分析该结构体的内存布局，尝试通过重新排列字段或使用 `Box` 来减少内存碎片。”*

## 3. AI 质量验收清单 (Validation Checklist)
- [ ] **编译通过**：代码是否在不修改的情况下直接通过 `cargo check`？
- [ ] **无不安全代码**：是否出现了不必要的 `unsafe` 块？如果有，是否提供了详尽的安全证明？
- [ ] **资源释放**：所有资源（如文件句柄、网络连接）是否在离开作用域时正确释放？
- [ ] **Trait 实现完整性**：是否实现了该类型应有的核心 Trait (如 `Debug`, `Clone`, `Default`) 以提升可用性？

## ❌ 常见 AI 误区 (Anti-Patterns)
- **过度 Clone**：为了快速通过借用检查器而到处调用 `.clone()`。$\rightarrow$ **正确做法**：通过引用传递或调整所有权结构。
- **生产环境 unwrap**：在逻辑中随意使用 `.unwrap()` 或 `.expect()`。$\rightarrow$ **正确做法**：使用 `Result` 传播错误或提供合理的 fallback。
- **过度封装**：将简单的结构体封装在不必要的 `Arc<Mutex<T>>` 中。$\rightarrow$ **正确做法**：优先考虑单线程所有权或轻量级并发原语。
