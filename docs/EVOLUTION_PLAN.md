# Sisyphus 进化规划 (Evolution Plan)

本文件定义了 Sisyphus 在完成初始战略路线图后的后续演进路径。目标是将系统从“自主项目架构师”进一步提升为“工业级通用认知引擎”。

## 总体战略
将开发重点从 **功能补全** 转向 **工业级鲁棒性**、**认知深度增强** 和 **生态开放性**。

---

## 第一阶段：短期增强 (P0 - Stability & Efficiency)
**目标**：消除基础设施瓶颈，提升基础认知检索的准确率。

### 1.1 存储层升级 (Structured Storage)
- **任务**: 将 `MfsStore` (简单 KV) 迁移至结构化数据库 (SQLite/PostgreSQL)。
- **目的**: 支持对 SOP 轨迹、路线图状态、执行日志进行复杂关联查询。
- **验收标准**: 
    - 实现 `SqliteStore` 接口。
    - 完成所有现有路线图数据的无损迁移。
    - 实现一个能够查询“高失败率节点”的分析接口。

### 1.2 经验库语义化 (Vector RAG)
- **任务**: 将 `ExperienceBank` 的 Jaccard 相似度检索升级为基于向量嵌入 (Vector Embeddings) 的语义检索。
- **目的**: 提高历史成功经验找回的准确率，实现从“字面相似”到“逻辑相似”的飞跃。
- **验收标准**: 
    - 集成向量数据库/库 (如 `faiss` 或 `qdrant`)。
    - 实现经验的向量化存储与检索流水线。
    - 对比测试证明语义检索在复杂任务上的召回率显著高于字面检索。

### 1.3 REST API 全面覆盖 (API Expansion)
- **任务**: 在 gRPC 基础上，为所有核心功能提供完整的 HTTP/JSON API。
- **目的**: 降低集成门槛，支持浏览器插件、IDE 插件等第三方客户端。
- **验收标准**: 
    - 覆盖 `SisyphusBridge` 的所有核心服务接口。
    - 提供完善的 OpenAPI (Swagger) 文档。

## 第二阶段：中期扩展 (P1 - Cognitive Depth)
**目标**：提升 SOP 的质量，增强执行过程中的预判能力。

### 2.1 模拟执行验证 (Simulation-based Verification)
- **任务**: 在 `predict` $\to$ `execute` 之间增加 `simulate` 阶段。
- **目的**: 在实际执行前，利用 LLM 或形式化验证在沙箱中模拟执行流，预判潜在死锁或逻辑漏洞。
- **验收标准**: 
    - 实现模拟执行引擎。
    - 能够拦截并修正 $\ge 20\%$ 的逻辑错误 SOP。

### 2.2 分布式技能市场 (Skill Ecosystem)
- **任务**: 实现技能的远程分发与安装机制。
- **目的**: 允许用户/社区分享经过验证的 $\text{SOP-Template}$ 和专用工具集。
- **验收标准**: 
    - 实现 `SkillRegistry` 的远程同步协议。
    *   支持通过 `Sisyphus` 客户端一键安装远程技能包。

### 2.3 多工作区协同 (Multi-Workspace)
- **任务**: 支持同时管理多个独立的项目路线图。
- **目的**: 提升多任务并行管理能力，并实现跨项目的知识迁移。
- **验收标准**: 
    - 实现 `WorkspaceManager` 管理多个 `Project` 实例。
    - 实现跨项目经验共享机制。

---

## 第三阶段：长期演进 (P2 - Autonomous Evolution)
**目标**：实现完全自主的认知迭代与自我进化。

### 3.1 自适应认知架构 (Dynamic Architecture)
- **任务**: 实现根据任务复杂度动态调整认知循环深度的机制。
- **目的**: 兼顾执行效率与思考深度，避免简单任务过度思考，复杂任务思考不足。
- **验收标准**: 
    - 实现认知深度动态开关。
    - 验证在相同目标下，资源消耗降低且成功率不下降。

### 3.2 可视化认知地图 (Visual Cognitive Map)
- **任务**: 构建基于 Web 的实时认知看板。
- **目的**: 将 `Project $\to$ Goal $\to$ SOP-DAG` 的映射关系可视化，实时监测认知瓶颈。
- **验收标准**: 
    - 实现实时同步的 DAG 拓扑图。
    - 支持在地图上直接修改目标或干预执行流。

### 3.3 闭环自我编程 (Self-Programming Loop)
- **任务**: 实现“发现缺口 $\to$ 编写工具 $\to$ 测试部署 $\to$ 转化为技能”的闭环。
- **目的**: 使 Sisyphus 能够自主扩展自己的工具集，不再依赖人工编写工具。
- **验收标准**: 
    - 实现自主工具开发流水线。
    - 验证系统能够自主创建并成功运行一个新的有效工具。
