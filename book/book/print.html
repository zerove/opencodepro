Sisyphus — Cognitive Computation Engine

Sisyphus — Cognitive Computation Engine

Sisyphus is a cognitive computation engine for building autonomous AI agents that plan, execute, and improve their behavior through a recursive observe–orient–decide–act (OODA) loop.

What It Does

At its core, Sisyphus takes a high-level goal (expressed in natural language) and:

  1. Synthesizes a Standard Operating Procedure (SOP) — a directed acyclic graph (DAG) of executable sub-steps.
  2. Executes the SOP in parallel across available nodes, respecting dependencies.
  3. Simulates outcomes via Monte Carlo tree search to predict success probability.
  4. Reflects on execution results — computing a deviation score between predicted and actual outcomes.
  5. Evolves the SOP — retrying failed nodes, increasing fuel budgets, or restructuring the graph.

This loop continues until the goal converges (deviation below threshold) or a maximum iteration limit is reached.

Why Sisyphus?

  • Self-improving: The engine learns from every execution, evolving its SOPs without human intervention.
  • Safe by design: WASM sandboxing for tool code execution with fuel limits and memory bounds.
  • Observable: Built-in Prometheus metrics for every cognitive operation.
  • Composable: Each crate is independent; use just the parts you need.

Project Status

Sisyphus is in active development (v0.1.0). The core cognitive loop is functional and tested, with WASM tool execution, multi-level caching, and Prometheus metrics integration.

Key Design Decisions

  • No async in trait methods: The system uses async_trait for trait methods that need async execution.
  • WASM-first tooling: All external tool code runs in sandboxed WASM instances with fuel and memory limits.
  • Metrics everywhere: Every significant operation records Prometheus metrics for observability.
  • Two-level cache: L1 (in-memory DashMap) + L2 (SQLite via sqlx) for fast key-value storage.

sisyphus-core — Kernel & Orchestration

The central crate that orchestrates the entire cognitive loop. Depends on all other crates.

Key Types

Main entry point for the cognitive loop. Holds references to all subsystems:

Executor

The DAG runner that executes SOP graphs with topological parallelism:

    .execute_with_context(&sop_graph, start_node, None)
    .await?;
}

CognitiveReport

Returned from execute_with_cognition:

pub struct CognitiveReport {
    pub deviation_score: f64,
    pub iterations: usize,
    pub trace: String,
    pub improvements: Vec<String>,
}
}

DependencyResolver

Resolves dependency mappings across composite graphs:

#![allow(unused)]
fn main() {
pub fn resolve(composite: &CompositeGraph) -> Result<Vec<String>, String>;
}

Execution Flow

  1. Synthesize: FlowSynthesizer::synthesize() converts a natural-language goal into an SOPGraph
  2. Execute: Executor::execute_with_context() runs the DAG with topological ordering — independent nodes run in parallel via tokio::task::JoinSet
  3. Simulate: MonteCarloSimulator estimates success probability and cost via random path sampling
  4. Reflect: StandardReflector compares prediction vs actual trace, producing a deviation score
  5. Evolve: If deviation > threshold, StandardEvolver mutates the SOP (fuel adjustment, retry wrappers)
  6. Loop: Repeat until convergence or max iterations

Benchmark Binary

cargo run --release -p sisyphus-core --bin integration_stress runs an end-to-end in-process stress test.

Example

#![allow(unused)]
fn main() {
use sisyphus_core::{SisyphusKernel, Executor, SOPGraph, WasmSOPNode};
use sisyphus_sandbox::WasmToolExecutor;
use std::sync::Arc;

// Build a single-node SOP
let executor = Arc::new(WasmToolExecutor::new()?);
let tool = WasmSOPNode {
    name: "greet".into(),
    tool_id: "hello".into(),
    executor: executor.clone(),
    fuel_limit: 1000,
};
let mut graph = SOPGraph::new();
let n = graph.add_node(Arc::new(tool));
let ctx = Executor::new().execute_with_context(&graph, n, None).await?;
}

sisyphus-intel — Cognition & Simulation

The “brain” of Sisyphus — four core cognitive capabilities: flow synthesis, simulation, reflection, and evolution.

Four Cognitive Traits

1. FlowSynthesizer (Synthesis)

Converts a natural-language goal into a DAG of typed actions:

#![allow(unused)]
fn main() {
#[async_trait]
pub trait FlowSynthesizer: Send + Sync {
    async fn synthesize(&self, goal: &str, context: &ExecutionContext)
        -> Result<SynthesisResult, String>;
}
}

Impl: GoalDrivenSynthesizer — keyword-based parser that maps action verbs (fetch, process, store, search, validate) to linear or parallel DAG pipelines.

2. Simulator (Prediction)

Estimates success probability and execution cost before running:

#![allow(unused)]
fn main() {
#[async_trait]
pub trait Simulator: Send + Sync {
    async fn simulate(&self, graph: &SOPGraph, ctx: &ExecutionContext, sop_id: &str)
        -> Result<SimulationResult, String>;
}
}

Impl: MonteCarloSimulator — random path sampling through the DAG. Computes blended path probabilities and estimated costs. Uses execution history from the state store to bias sampling toward historically successful paths.

3. Reflector (Analysis)

Compares predicted vs actual outcomes:

#![allow(unused)]
fn main() {
#[async_trait]
pub trait Reflector: Send + Sync {
    async fn reflect(&self, trace: &str, prediction: &SimulationResult)
        -> Result<ReflectionReport, String>;
}
}

Impl: StandardReflector — string-based error classification building a deviation score (0.0 = perfect match). Generates structured improvement suggestions.

4. SOPEvolver (Adaptation)

Mutates the SOP after reflection:

#![allow(unused)]
fn main() {
#[async_trait]
pub trait SOPEvolver: Send + Sync {
    fn evolve(&self, graph: &SOPGraph, report: &ReflectionReport, prediction: &SimulationResult)
        -> Result<SOPGraph, String>;
}
}

Impl: StandardEvolver — wraps failed nodes in retry logic, adjusts fuel budgets. Uses either SimpleFuelPricer (linear) or AdaptiveFuelPricer (exponential backoff).

Error Classification

ErrorCategory classifies execution failures:

#![allow(unused)]
fn main() {
pub enum ErrorCategory {
    ResourceExhaustion(&'static str),
    Timeout,
    DataError,
    Unknown,
}
}

Used by StandardReflector to determine severity and generate targeted improvement suggestions.

Example

#![allow(unused)]
fn main() {
use sisyphus_intel::*;

let executor = Arc::new(MockExecutor);
let synthesizer = GoalDrivenSynthesizer::new(executor);
let ctx = ExecutionContext::new();
let result = synthesizer.synthesize("fetch process store", &ctx).await?;
println!("Graph has {} nodes", result.graph.graph.node_count());
}

sisyphus-mem — Memory & Caching

Two-level key-value store for SOP execution history, intermediate results, and configuration state.

Architecture

┌──────────┐   write-through    ┌──────────┐
│   L1     │ ◄──────────────── │   L2     │
│ DashMap  │    (L2 → L1)      │  SQLite  │
│ (memory) │ ────────────────► │  (disk)  │
└──────────┘    read-through    └──────────┘
                 (L1 → L2)
  • L1: In-memory DashMap<String, serde_json::Value> — sub-millisecond reads
  • L2: SQLite via sqlx — persistent storage, WAL mode for concurrency

Key Type: MfsStore

#![allow(unused)]
fn main() {
pub struct MfsStore {
    l1: Arc<DashMap<String, serde_json::Value>>,
    l2: SqlitePool,
}
}

Construction

#![allow(unused)]
fn main() {
// In-memory (for testing)
let store = MfsStore::new("sqlite::memory:").await?;

// Persistent
let store = MfsStore::new("sqlite:data/state.db").await?;
}

WAL mode and synchronous=NORMAL are enabled automatically for performance.

Read/Write Strategy

OperationPathAtomicity
set(key, value)Write to L2 SQLite → update L1 DashMapL2 write is a single SQL INSERT OR REPLACE
get(key)Check L1 → miss? → query L2 → populate L1L1 get is lock-free DashMap read
snapshot()Dump all entries into Snapshot structCaptures L2 snapshot via SELECT *
restore(snapshot)Clear and reload from snapshotTruncates table, bulk insert

Example

#![allow(unused)]
fn main() {
use sisyphus_mem::MfsStore;

let store = MfsStore::new("sqlite::memory:").await?;
store.set_state_json("my_key", serde_json::json!({"hello": "world"})).await?;
let val = store.get_state_json("my_key").await?;
assert_eq!(val, Some(serde_json::json!({"hello": "world"})));
}

sisyphus-sandbox — WASM Runtime

Provides a sandboxed WASM runtime for executing tool code safely using Wasmtime.

Key Type: WasmToolExecutor

#![allow(unused)]
fn main() {
pub struct WasmToolExecutor {
    engine: Engine,
    tools_path: PathBuf,
    module_cache: Arc<DashMap<String, Module>>,
}
}

Construction

#![allow(unused)]
fn main() {
// Default — looks for tools/ relative to CWD
let exec = WasmToolExecutor::new()?;

// Custom path and memory limit
let exec = WasmToolExecutor::with_config(
    Some(PathBuf::from("/opt/tools")),
    Some(20),  // pages (20 × 64 KiB = 1.25 MiB)
)?;
}

Creates a Wasmtime Engine with:

  • Pooling instance allocation: Pre-allocated memory pools for fast instantiation
  • Memory limits: Configurable max memory per instance (default: 10 pages = 640 KiB)
  • Fuel metering: Configurable fuel limits to prevent runaway execution (default: 10,000)
  • Stack limit: 1,000,000 max WASM stack frames

Execution Flow

  1. Load: Read .wasm binary from {tools_path}/{tool_id}.wasm
  2. Compile: Compile into a Wasmtime Module (cached in DashMap to avoid recompilation)
  3. Instantiate: Create an instance with per-call fuel allocation
  4. Call: Invoke the exported run function, passing input bytes
  5. Return: Return output bytes, or a fuel/memory exhaustion error
#![allow(unused)]
fn main() {
#[async_trait]
impl ToolExecutor for WasmToolExecutor {
    async fn execute(&self, tool_id: &str, args: Vec<u8>, fuel_limit: u64) -> Result<Vec<u8>, String> {
        // ...
    }
}
}

Error Handling

ErrorMeaningCognitive Loop Response
ResourceExhausted: fuelRan out of WASM instructionsRetry with 2× fuel
ResourceExhausted: memoryExceeded linear memory limitFail — redesign node
Unknown export: runWASM module has no run exportFail — invalid tool
I/O errorTool file not foundFail — missing tool

Fuel System

Wasmtime’s fuel metering tracks WASM instruction consumption. When fuel runs out, execution is immediately aborted. The cognitive loop interprets this as a signal to retry with increased fuel via AdaptiveFuelPricer.

Console Output Capture

WASM module stdout/stderr is captured via WasmtimeConsole and routed through tracing.

Key Concepts

  • Standard Operating Procedure (SOP) — DAG representation of executable procedures
  • Cognitive Loop — The recursive observe–orient–decide–act cycle
  • DAG Execution — Parallel execution with dependency resolution

Standard Operating Procedure (SOP)

An SOP is a directed acyclic graph (DAG) that represents a procedure to achieve a specific goal.

Structure

graph LR
    G[Goal] --> N1[Node 1<br/>fetch data]
    G --> N2[Node 2<br/>process]
    G --> N3[Node 3<br/>validate]
    N1 --> N4[Node 4<br/>merge]
    N2 --> N4
    N3 --> N4
    N4 --> R(Result)

Each node contains:

  • Name: Unique identifier within the SOP
  • Description: Semantic description of the step (used for synthesis and reflection)
  • Tool Type: Which WASM tool binary to invoke
  • Fuel Budget: WASM instruction limit for this node (default: 10,000)
  • Max Retries: How many times to retry on failure
  • Timeout: Maximum wall-clock time (default: 30s)

Lifecycle

stateDiagram-v2
    [*] --> Synthesized: GoalDrivenSynthesizer
    Synthesized --> Executing: DagExecutor
    Executing --> Succeeded: All nodes OK
    Executing --> Failed: Node error
    Failed --> Evolved: StandardEvolver
    Evolved --> Executing: Retry with modifications
    Succeeded --> [*]
    Failed --> [*]: Max iterations exceeded
  1. Synthesize: GoalDrivenSynthesizer generates an SOP graph from a natural-language goal
  2. Execute: Executor runs the DAG with topological ordering — independent nodes in parallel
  3. Evolve: After reflection, the SOP may be mutated — new nodes added, fuel budgets adjusted, or subgraphs restructured

Evolution Operations

OperationDescription
Retry wrapperWrap a failed node with retry logic (increased fuel)
Fuel increaseBoost fuel budget for nodes that exhausted fuel (2× per retry)
Subgraph restructureReorder or split nodes for better parallelism (future)

Cognitive Loop

The recursive OODA-inspired cycle that drives Sisyphus’s self-improvement behavior.

Sequence Diagram

sequenceDiagram
    participant U as User
    participant B as Bridge
    participant K as SisyphusKernel
    participant Synth as GoalDrivenSynthesizer
    participant Exec as Executor
    participant Sim as MonteCarloSimulator
    participant Ref as StandardReflector
    participant Evo as StandardEvolver

    U->>B: ExecuteGoal("summarize data")
    B->>K: execute_goal()
    K->>Synth: synthesize(goal)
    Synth-->>K: SOPGraph DAG

    loop Until convergence (max 10 iterations)
        K->>Sim: simulate(graph)
        Sim-->>K: SimulationResult

        K->>Exec: execute_with_context(graph)
        Exec-->>K: ExecutionContext

        K->>Ref: reflect(trace, prediction)
        Ref-->>K: ReflectionReport

        alt deviation > threshold
            K->>Evo: evolve(graph, report)
            Evo-->>K: Mutated SOPGraph
            K-->>K: Loop back to execute
        else deviation <= threshold
            K-->>B: CognitiveReport (converged)
        end
    end

    B-->>U: SOPResponse { status, result }

Key Implementation: execute_with_cognition()

#![allow(unused)]
fn main() {
// Simplified from sisyphus-core
async fn execute_with_cognition(
    &self, graph: &SOPGraph, start: NodeIndex, sop_id: &str, ...
) -> Result<(NodeOutput, String, Option<SOPGraph>), String> {
    let mut current_ref = graph.clone();
    let max_iter = 10;

    for iteration in 0..max_iter {
        // 1. Predict outcome
        let prediction = intel.simulator.simulate(&current_ref, &ctx, sop_id).await?;

        // 2. Execute the SOP
        let final_ctx = executor.execute_with_context(&current_ref, start, None).await?;

        // 3. Build trace and reflect
        let trace = build_trace(&current_ref, &final_ctx);
        let reflection = intel.reflector.reflect(&trace, &prediction).await?;

        // 4. Check convergence
        if reflection.deviation_score < CONVERGENCE_THRESHOLD {
            return Ok((result, report, None));  // Done
        }

        // 5. Evolve and retry
        let evolved = intel.evolver.evolve(&current_ref, &reflection, &prediction)?;
        current_ref = evolved;
    }

    Err("Max iterations exceeded".into())
}
}

Convergence Conditions

The loop terminates when any of:

  • Deviation threshold: deviation_score < 0.15 (predictions match actuals)
  • Max iterations: Loop runs 10 times without converging
  • No evolution: Evolver returns Ok(graph) with identical structure (no changes possible)

DAG Execution

Sisyphus executes SOP graphs using a parallel topological executor based on in-degree tracking.

Algorithm

flowchart TD
    A[Compute in-degree for all nodes] --> B{Find nodes<br/>with in-degree = 0}
    B --> C[Spawn ready nodes<br/>via tokio::JoinSet]
    C --> D[Wait for ANY node<br/>to complete]
    D --> E[Decrement in-degree<br/>of downstream nodes]
    E --> F{New nodes<br/>ready?}
    F -->|Yes| C
    F -->|No| G{All nodes<br/>done?}
    G -->|Yes| H[Return<br/>ExecutionContext]
    G -->|No| D

Parallelism Model

Nodes with no dependency relationship execute simultaneously:

Code: Core Executor

#![allow(unused)]
fn main() {
// Simplified from sisyphus-core::Executor
pub async fn execute_with_context(
    &self, sop_graph: &SOPGraph, start_node: NodeIndex, initial_ctx: Option<Arc<ExecutionContext>>,
) -> Result<Arc<ExecutionContext>, String> {
    // Validate acyclic
    toposort(&sop_graph.graph, None).map_err(|_| "SOPGraph contains cycles")?;

    let ctx = initial_ctx.unwrap_or_else(|| Arc::new(ExecutionContext::new()));
    let mut join_set = JoinSet::new();
    let mut in_degree: HashMap<NodeIndex, usize> = HashMap::new();

    // Initialize in-degree counts
    for node in sop_graph.graph.node_indices() {
        let degree = sop_graph.graph.edges_directed(node, Incoming).count();
        in_degree.insert(node, degree);
        if degree == 0 {
            let ctx = ctx.clone();
            let node = sop_graph.graph[node].clone();
            join_set.spawn(async move { node.execute(&ctx).await });
        }
    }

    // Process results as they complete
    while let Some(result) = join_set.join_next().await {
        let (node_id, output) = result.map_err(|e| format!("Join error: {}", e))??;
        // Store output in context
        ctx.set(&sop_graph.graph[node_id].name(), output).await;
        // Fan-out to downstream nodes
        for edge in sop_graph.graph.edges_directed(node_id, Outgoing) {
            let target = edge.target();
            let degree = in_degree.get_mut(&target).unwrap();
            *degree -= 1;
            if *degree == 0 {
                // Spawn the now-ready node
            }
        }
    }

    Ok(ctx)
}
}

Error Handling

  • Cycle detection: toposort() rejects cyclic graphs before execution begins
  • Node errors: Propagated up; the cognitive loop catches them and evolves the SOP
  • Join errors: Tokio task panics are caught and returned as errors

Fuel & Memory

Each node executes with its configured fuel budget. Wasmtime’s fuel metering tracks WASM instruction consumption. Exhaustion triggers ResourceExhausted, which the cognitive loop uses to adjust fuel for retries.
